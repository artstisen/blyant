# Changes

## v0.1.0 (in progress)
- **Blyant starts from Marbles v1.5.3**: the program, the project and its files are renamed from Marbles to Blyant (the namespace, `Blyant.sln`, the folders `Blyant` and `Blyant.Tests`, the program `Blyant` / `Blyant.exe`, the archives `Blyant-0.1.0-*.zip` and the language pack). The built-in logo spells BLYANT, and the color scheme _Marbles Quest_ is now _Blyant Quest_.
- **No encrypted notes**: the data files of Marbles (`.mbls`), the encryption, the login page, Note Management (the main menu, the lists of entries and the notes in the editor), the merge and export tool, backups of data files and the password generator (`:pw` in the editor) are removed. A `.mbls` file is an ordinary file in the file browser. With them went the settings `onlymode`, `stayloggedin`, `clipboardnotes`, `file`, `subdir` and `backup` (left out when the settings file is read), the Data files tab of the Jump menu, `:logout`, `:title` in the editor, and the commands of the main menu (`:language`, `:size`, `:bw`, `:number`, `:defaults` ...: their settings are on the Configuration tab of the start page). Bookmarks and jumps to data files, kept by Marbles in `bookmarks.txt` and `jump.txt`, are left out.
- **Start page**: the first tab is **Start**, with **New file** (`N`), **File browser** (`F`), **New project** (`P`), **Open project** (`O`), the **Jump menu** (`M` or `Ctrl+O`), the **Quick guide** (`U`) and **Exit**. The start page is shown again when the file browser is closed. Commands: `:new name`, `:file` (`:open`), `:project name`, `:projects` and `:start`.
- **Projects**: a project is a folder in the **projects folder** (setting `projectsdir`, by default `Blyant-Projects` in your Documents folder; set on the General page of Configuration). New project makes the folder and shows it in the file browser; Open project lists the projects, with what each holds. New file makes the file in the directory the file browser was in last. A page for managing the files of a project is planned.
- **The list of projects**: `C` picks the color of a project (with the list of colors; kept as `color=` in the file `.blyant` in the project), and `N` opens the note of a project in the editor (the Markdown file `.blyant-note.md` in the project; one left empty is removed). The start of the note is shown to the right of what the project holds. `I` shows information about the project (as in the Jump menu), `?` shows the keys of the list, and the list has a command line: `:info`, `:path` and `:name` (copy the path or the name of the folder), `:color`, `:note`, `:help` and `:q`. Both files go with the folder of the project, and are not listed with what it holds.
- **Projects on all systems**: a new project may not have the name of another in other upper or lower case (on Linux both could be made, but not on Windows or macOS, where the folder may be synced to). In the setting `projectsdir`, `~` is the home directory, and a folder that is not a full path on the system (`C:\Users\...` on Linux) is not used. The default projects folder is in the Documents folder on Windows, macOS and Linux alike (on Linux `XDG_DOCUMENTS_DIR`, or `~/Documents`).
- **File browser**: it starts in the projects folder (or the home directory), and `:home` goes there. `E` (or `:projects`) shows the projects in a list, and the one picked in the pane with the focus (also while the place to copy or move to is selected). `:pro` (and `:proj`) is short for `:projects` on the start page, in the file browser and in the editor.
- **The default projects folder is `Blyant-Projects`** (in the Documents folder), not `Blyant`: that is the name a folder for the program gets, and the program, its data directory and your writing should not share a folder. A projects folder set in the settings file (`projectsdir`) is kept.
- **Deleting goes to the trash**: `D` and `:delete` in the file browser move files and directories to `trash` in the data directory (for all that is deleted, in a project or not; it goes with the data directory when Blyant is copied or backed up), with the time in front of the name (`2026-10-22 14.03.11 chapter 1.md`), and `trash.txt` there tells where each came from. `:trash` goes there; deleting in the trash is for good. _Delete to trash_ on the General page of Configuration (setting `deletetotrash`, on from the start) turns it off. What cannot be moved to the trash is only deleted for good if you say so.
- **The question before deleting is not answered by typing**: `Y` does nothing in it, and only `Enter` picks the choice selected with `j` `k` (Space and `l` do not). Before, text typed in the file browser by mistake (meant for the editor) could delete files: `d` asked, and the `y` of "today" answered, or the `k` of "dark " selected _Yes_ and the space picked it.
- **The projects folder is chosen at the first project**: no projects folder is set from the start, and none is made. At the first new project you are asked where projects go: `Blyant-Projects` in Documents, another folder, or none (then you pick where each new project is made; setting `projectsask`). _Projects folder_ in Configuration asks the same. A projects folder already in the settings file is kept.
- **Projects from anywhere**: a folder you already have is added to the projects with `A` (`:add`) in the list of projects, or `:project add` in the file browser; `D` (`:remove`) takes it off the list again (the folder stays). The added folders are kept in `projects.txt` in the data directory, follow the folder when it is renamed or moved in the file browser, and one that is gone is shown as _(missing)_. `P` (`:new`) in the list makes a new project. Picking a folder (to add, to make a project in, or the projects folder) opens where the last folder was picked, with it selected, or where the last picking was canceled (setting `pickdir`). The two parts below the list are labeled _Files_ (where the project is and what it holds) and _Note_. With projects both in the projects folder and added, the list has the tabs _All_, _Added_ and _Projects folder_ (`Tab`), and the Jump menu shows them all.
- **The trash is in the data directory**: `trash` next to `recovery` and `log.txt`, for all that is deleted, in a project or not, so it goes with the data directory when Blyant is copied or backed up.
- **All file operations are logged**: besides those of the file browser, all that Blyant does with files by itself is in the log, with the path: files made and saved (also your text with `:w`, the settings, the lists and the recovery copies), added to, renamed, copied and deleted, and the directories it makes (the data directory, the projects folder, `trash`, `recovery` ...), with the reason when one failed. What is written is never logged.
- **Blank page**: `B` (or `:blank`) on the start page opens the editor at once on an empty Markdown page: write first, and decide what and where to save it as when you save (`:w` asks for the name and the folder, as New file does; `:w name` fills in the name). It has a recovery copy of its own while it is not saved.
- **The help is colored** as the quick guide: the headings of the sections in the color of headings, the keys in the accent color of the color scheme.
- **`:import favorites`** on the Bookmarks tab of the Jump menu copies the favorites of the file browser into the bookmarks, with their folders, colors and order (after asking, with what will be added). Places that are bookmarks already are left out, a folder with the name of a bookmark folder is added to it, and favorites whose file is gone are copied too. The favorites stay as they are.
- **No limit to the bookmarks**: there could be at most 100 before.
- **`:protect off`** in the file browser lifts the protection of Blyant's own files (the data directory, `settings.ini`, `favorites.txt`, `history.txt`) for the session, so they can be renamed, moved and deleted; `:protect on` restores it, and it is on again at every start. _UNPROTECTED_ shows at the top right while it is off, and the question before deleting tells that Blyant uses the file.
- **Columns in the lists of the file browser**: the favorites, the file history, the directory hotlist and the search results have lines between their columns and labels in the divider line, so a long list is easier to read: _Name_, _Path_ and _Info_ in the favorites (size, `<DIR>`, _(missing)_, number of favorites) and the search results (_Line_ in place of _Path_ when a text was searched), _Name_, _Path_ and _Opened_ in the history, _Name_ and _Path_ in the hotlist.
- **Start on a blank page**: a third choice for startup on the General page of Configuration (`startmode=blank`): Blyant opens on a blank page, and the start page comes when it is closed.
- **The kind of new files**: _New files and blank pages_ on the General page picks the kind of a new file whose name has no extension, and of a blank page: Markdown (the default), plain text, HTML, CSS, JavaScript, JSON, XML, C#, PHP or INI (setting `filetype`). It is used by `N` and `:new` on the start page, in the file browser and in the editor, and a blank page is colored as that kind.
- **Recover unsaved text**: `R` (or `:recover`) on the start page, shown only while there are recovery copies, lists them (blank pages and files, the newest first, with the start of the text) to open one, or `D` to delete one.
- **The Default color scheme** highlights the tab with the focus (cyan on black), with a white corner.
- **_Open file_ on the start page is now _File browser_**, as it does more than open files (the key is still `F`, and `:file` and `:open` still work).
- **New file in another folder**: on the start page, `Tab` in the box of a new file (`N`, `:new`) chooses the folder: the folders of the two panes of the file browser, the folder picked last and the projects folder (`1` to `4`, or `j`/`k`, `gg`/`G` and `Enter`), or `B` to pick one in the file browser. The name typed is kept. `:new name` shows the box too, with the name filled in.
- **Fixes from a code review**:
  - A recovery copy put off with _Decide later_ was written over by the next change of the file. Now the new changes get a copy beside it, and both are kept
  - `p`, `P`, `:dup` and a block put on the last line of a read-only text (a peek, a comparison) stopped the editor with an error. They are refused, as other changes are
  - When the list of added projects (`projects.txt`) could not be read for a moment (held by a sync program), adding a project wrote a list with only that one. Now it is not changed, and you are told
  - Saving the settings file from the editor did not tell when the write failed, and marked the text as saved
  - The paste bin file could be one of Blyant's own files (as `settings.ini`), which every yank then replaced
  - The data directory is chosen once: a folder `data` made later in the directory Blyant was started in no longer takes its place in the middle of a session
  - A count given to `.` takes the place of the count of the change, as in Vim (`3x` and then `2.` deletes 2 characters, not 6)
  - Shell scripts: a here-string (`<<<`) and a shift in arithmetic (`$((1 << n))`) are no longer read as the start of a here-document
  - Rust: a raw string over several lines (`r#"...`) ends at its own end (`"#`), not at a quote in it
- **More fixes from the code review**:
  - The bottom line of the editor no longer runs past the edge when all that is at its right (spelling, recording, the kind of file ...) is wider than the window: only the line and column are kept
  - C and C++: a comment on a line of the preprocessor (`#include "a.h" /* ...`) is colored as a comment, and goes on to the next lines
  - Markdown: a block of code ends only at a fence of the same kind (```` ``` ```` or `~~~`), at least as long, with nothing after it
  - `gU`, `gu` and `~` change case the same way whatever the language of the computer is (on a Turkish system `i` became `İ`)
  - Smartcase: a letter after a backslash (`\S`) no longer makes a search match case
  - `blyant --help` and `blyant --version` (also `-h`, `-v`) are answered in the terminal; before, `--help` was offered as a file to make
  - `B` in the Jump menu no longer forgets the bookmark that `u` could put back
  - The languages are picked with `1` to `9` and then letters: with 10 or more, typing `1` picked the first at once
  - Texts cut for the screen count terminal cells (wide characters take two), and a text that fits exactly is no longer cut
- **A picture of h, j, k and l** in the quick guide and the editor guide shows them as the arrow keys they are, below their rows.
- **PowerShell, batch files and shell scripts are colored**: `.ps1` (`.psm1`, `.psd1`), `.bat` and `.cmd`, and `.sh` (`.bash`, `.zsh`, `.bashrc`) files get colors in the editor: comments, strings (here-strings and here-documents over several lines), the words of the language, numbers, and as names the variables (`$name`, `%name%`, `${name}`) and the labels of batch files. A file without an extension is colored by its first line, as `#!/bin/bash`, `#!/usr/bin/env python3` or `#!/usr/bin/env pwsh` tells. `:syntax ps`, `:syntax bat` and `:syntax sh` color a text as one of them.
- **C, C++, Rust and Python are colored**: `.c`, `.h`, `.cpp`, `.hpp` (and the other names of C++ files), `.rs`, and `.py`, `.pyw` and `.pyi` files get colors in the editor, in the colors of C#: comments, strings, the words of the language, numbers, and as names the lines of the preprocessor (C/C++), attributes and lifetimes (Rust) and decorators (Python). Macros in Rust (`println!`) are colored as words. Raw strings of C++ and Rust and strings in three quotes in Python go over several lines. `:syntax cpp` (or `c`), `:syntax rust` and `:syntax py` color a text as one of them.
- **Settings files are colored**: `.ini` files (and `.cfg`, `.conf`, `.editorconfig`) get colors in the editor: comments, `[sections]`, the names, and the values (numbers, `true`/`false` and the like, and text). Blyant's own `settings.ini` is colored too, also when edited from Configuration. `:syntax ini` colors any text as INI.
- **The type of `.blyant` files**: the file browser and the bottom line of the editor show the type of a file whose name starts with a dot and has no other extension, as the information box (`I`) does: `.blyant` is `BLYANT`, `.gitignore` is `GITIGNORE`. Before, it was left empty.
- **Recovery copies**: while a file has changes that are not saved, a copy of the text is kept in `recovery` in the data directory: written when you stop typing for 2 seconds (and at least every 30 seconds), and when the terminal window is closed or the computer shuts down. It is removed when the text is saved or the changes are given up. Opening a file that has a copy asks what to do: open the recovered text, show the differences, keep the file as it is, or decide later. `:recovery` in the file browser goes to the copies; the setting `recovery` (Configuration, Editor) turns them off. The same on Windows, Linux and macOS.
- **Files are never emptied before they are written**: the paste bin is now replaced safely too (written to a temporary file first, as files are saved), and making a new file (`N` in the file browser, or a file given at startup) never empties a file that has come in the meantime. A peek can never be saved.
- **The log is written to `log.txt`** in the data directory, with the date, so it can be read after Blyant is closed; at startup a file larger than 1 MB is renamed `log.old.txt`. Deletions tell whether they went to the trash.
- **Jump menu**: a **Projects** tab after Recent, with the projects in their colors; `Enter` shows the one picked in the file browser.
- **Color scheme Bright Typist**: a new built-in scheme with black text on a white background, as on paper, and dark blue, dark yellow and dark magenta for the colors of Markdown and other files.
- **Automatic size is on from the start**: the screen follows the size of the terminal window, also after _Reset all settings_, and with a settings file that does not have `autosize` in it (`autosize=false` turns it off).
- **Ctrl+C** does not close Blyant any more, which lost text that was not saved: the editor tells how to close it (`:q`). Where the terminal has a selection, `Ctrl+C` still copies it.
- **The editor follows the terminal window** when it is resized (with _Automatic size_ on), also on Linux and macOS, where a resize was not noticed: when the size has stayed the same for a moment, the text is wrapped in the new width (a split keeps half for each pane) and drawn again. Before, the text could stay blank after a resize. With a fixed size, the question about a window that is too small goes away by itself when the window is made large enough.
- **Peek** (`V`, `:peek`) keeps the focus in the list: the peek follows the selection, so files are gone through with `j` and `k`. `Tab` goes into the peek (to scroll and search; `Tab` or `Esc` goes back). The pane of the peek is labeled PEEK, with the name of the file at its top, and `V` or `Esc` ends it, as do the keys that use the other pane. The peek shows the file without word wrap, also when the setting `wrap` is on; `:wrap` in a peek is for that peek only, and is not saved.
- **Editor**: `:projects` (`:proj`) shows the projects in a list; the one picked is shown in the file browser, as a jump (changes that are not saved are asked about first).
- **New files are Markdown**: a new file whose name has no extension gets `.md` (`chapter 1` is `chapter 1.md`): `N` and `:new` in the file browser, New file on the start page, and `:new` in the editor. A name that starts with a dot (`.gitignore`) is kept as it is.
- **The list of colors** (the colors of a scheme, of a favorite, a bookmark or a folder): each color has a letter that picks it at once, as the choices of the start page: `A` Black ... `U` White (leaving out `g` `j` `k` `l` `q`, which the list uses), and `X` for _[Default]_. `1` to `9` select the first nine colors.
- **Completing words**: the words of the Markdown list and of the list for all text in a new `completions.txt` start with `/`, so they are not offered while you write prose (`co` no longer offers a code block): `/h1` to `/h6` (headings), `/bold` (`**$0**`), `/italic` (`*$0*`), `/bolditalic`, `/strike`, `/inline` (code in a line), `/quote`, `/list`, `/numbered`, `/task`, `/done`, `/code`, `/table`, `/hr`, `/link`, `/image`, `/url`, `/footnote`, `/footdef`, `/frontmatter`, `/comment`, `/note`, `/warning`, `/todo` and `/lorem`. The word `JavaScript` is in the JavaScript list. A file made before keeps its lists. When the whole word of a completion is typed (`/bold`, with `/bolditalic` shown too), `Tab` completes with it at once. A completion is shown with `...` where the cursor goes (`**...**`, `<div>...</div>`), so one of marks only can be read. Completing is on from the start, and the file is made at startup when there is none, so it is ready the first time (a file that is there is never written over; a settings file with `autocomplete=false` keeps it off).
- **Startup**: `startmode` is `select` (the start page) or `editor` (the file browser); `notes`, of Marbles, shows the start page.
- **Help, guides**: the help, the quick guide and the short guides tell of files and projects; the Note Management guide is now the **Projects guide**. The guides are `Guide-to-start-page.md` (the start page, projects and the file browser) and `Guide-to-jump-menu.md` (the Jump menu, color schemes and logos).
- **Its own data**: when the program directory cannot be written to, Blyant keeps its data in `Blyant/data` in the user's application data (Marbles uses `Marbles/data`), so the two programs can be used side by side.
- **Language files** start with `# Blyant: name (code)`.
- The history of changes before this is that of Marbles, found in its own repository.
