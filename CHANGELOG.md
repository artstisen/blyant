# Changes

## Unreleased
- **Line numbers in the favorites and the bookmarks, and a Lists page in Configuration**: `:number` (and `:nonumber`) numbers the rows of the favorites, or of the Bookmarks tab of the Jump menu, dimmed at the left, as `12gg` and `5j` count them; the pointer and the names move to the right of the numbers, which are as wide as the largest. Off from the start (settings `favoritenumbers`, `bookmarknumbers`). The new **Lists** page of Configuration (between Editor and System, `:lists`) has the line numbers, the panes and the peek of both lists; the peek is dimmed while its panes are off, and all six go back to their defaults when the settings are reset.
- **Save a copy, and save as**: `:w name` in the editor saves a copy of the text as a new file next to the file (with the file's extension if the name has none, and its encoding and line endings), and the file stays open as it is; `:saveas name` does the same and edits the new file from then on (`:saveas` alone asks for the name). A file of that name is replaced only after asking. When the file is a favorite, you are asked whether the new file goes below it in the favorites (copies of the same favorite keep the order they were made in). Back in the file browser or the favorites, the last file written is selected. (`:w name` saved only a comparison before.)

## v1.0.0 (2026-10-26)
- **Blyant starts from Marbles v1.5.3**: the program, the project and its files are renamed from Marbles to Blyant (the namespace, `Blyant.sln`, the folders `Blyant` and `Blyant.Tests`, the program `Blyant` / `Blyant.exe`, the archives `Blyant-1.0.0-*.zip` and the language pack). The built-in logo spells BLYANT, and the color scheme _Marbles Quest_ is now _Blyant Quest_.
- **No encrypted notes**: the data files of Marbles (`.mbls`), the encryption, the login page, Note Management (the main menu, the lists of entries and the notes in the editor), the merge and export tool, backups of data files and the password generator (`:pw` in the editor) are removed. A `.mbls` file is an ordinary file in the file browser. With them went the settings `onlymode`, `stayloggedin`, `clipboardnotes`, `file`, `subdir` and `backup` (left out when the settings file is read), the Data files tab of the Jump menu, `:logout`, `:title` in the editor, and the commands of the main menu (`:language`, `:size`, `:bw`, `:number`, `:defaults` ...: their settings are on the Configuration tab of the start page). Bookmarks and jumps to data files, kept by Marbles in `bookmarks.txt` and `jump.txt`, are left out.
- **Start page**: the first tab is **Start**, with **New file** (`N`), **File browser** (`F`), **New project** (`P`), **Open project** (`O`), the **Jump menu** (`M` or `Ctrl+O`), the **Quick guide** (`U`) and **Exit**. The start page is shown again when the file browser is closed. Commands: `:new name`, `:file` (`:open`), `:project name`, `:projects` and `:start`.
- **Projects**: a project is a folder with the files of a piece of writing, anywhere on your computer. New project makes the folder in a folder you pick and shows it in the file browser; Open project lists the projects, with what each holds. New file makes the file in the directory the file browser was in last.
- **The list of projects**: `C` picks the color of a project (with the list of colors; kept as `color=` in the file `.blyant` in the project), and `N` opens the note of a project in the editor (the Markdown file `.blyant-note.md` in the project; one left empty is removed). The start of the note is shown to the right of what the project holds. `I` shows information about the project (as in the Jump menu), `?` shows the keys of the list, and the list has a command line: `:info`, `:path` and `:name` (copy the path or the name of the folder), `:color`, `:note`, `:help` and `:q`. Both files go with the folder of the project, and are not listed with what it holds.
- **Projects on all systems**: a new project may not have the name of another in other upper or lower case (on Linux both could be made, but not on Windows or macOS, where the folder may be synced to).
- **File browser**: it starts in the home directory the first time, and `:home` goes there. `E` (or `:projects`) shows the projects in a list, and the one picked in the pane with the focus (also while the place to copy or move to is selected). `:pro` (and `:proj`) is short for `:projects` on the start page, in the file browser and in the editor.
- **Deleting goes to the trash**: `D` and `:delete` in the file browser move files and directories to `trash` in the data directory (for all that is deleted, in a project or not; it goes with the data directory when Blyant is copied or backed up), with the time in front of the name (`2026-10-22 14.03.11 chapter 1.md`), and `trash.txt` there tells where each came from. `:trash` goes there; deleting in the trash is for good. _Delete to trash_ on the General page of Configuration (setting `deletetotrash`, on from the start) turns it off. What cannot be moved to the trash is only deleted for good if you say so.
- **The question before deleting is not answered by typing**: `Y` does nothing in it, and only `Enter` picks the choice selected with `j` `k` (Space and `l` do not). Before, text typed in the file browser by mistake (meant for the editor) could delete files: `d` asked, and the `y` of "today" answered, or the `k` of "dark " selected _Yes_ and the space picked it.
- **Projects from anywhere**: a folder you already have is added to the projects with `A` (`:add`) in the list of projects, or `:project add` in the file browser; `D` (`:remove`) takes it off the list again (the folder stays). The projects are kept in `projects.txt` in the data directory, follow the folder when it is renamed or moved in the file browser, and one that is gone is shown as _(missing)_. `P` (`:new`) in the list makes a new project. Picking a folder (to add, or to make a project in) opens where the last folder was picked, with it selected, or where the last picking was canceled (setting `pickdir`). The two parts below the list are labeled _Files_ (where the project is and what it holds) and _Note_.
- **The trash is in the data directory**: `trash` next to `recovery` and `log.txt`, for all that is deleted, in a project or not, so it goes with the data directory when Blyant is copied or backed up.
- **All file operations are logged**: besides those of the file browser, all that Blyant does with files by itself is in the log, with the path: files made and saved (also your text with `:w`, the settings, the lists and the recovery copies), added to, renamed, copied and deleted, and the directories it makes (the data directory, `trash`, `recovery` ...), with the reason when one failed. What is written is never logged.
- **Blank page**: `B` (or `:blank`) on the start page opens the editor at once on an empty Markdown page: write first, and decide what and where to save it as when you save (`:w` asks for the name and the folder, as New file does; `:w name` fills in the name). It has a recovery copy of its own while it is not saved.
- **The help is colored** as the quick guide: the headings of the sections in the color of headings, the keys in the accent color of the color scheme.
- **`:import favorites`** on the Bookmarks tab of the Jump menu copies the favorites of the file browser into the bookmarks, with their folders, colors and order (after asking, with what will be added). Places that are bookmarks already are left out, a folder with the name of a bookmark folder is added to it, and favorites whose file is gone are copied too. The favorites stay as they are.
- **`:import bookmarks`** in the list of favorites copies the bookmarks of the Jump menu into the favorites, the other way from `:import favorites` and by the same rules: with their folders, subfolders, colors, notes and order, after asking with what will be added; places that are favorites already are left out, and a folder with the name of a folder of the favorites is added to it. Bookmarks of pages of Blyant are left out and counted (a favorite is a file or a directory), and the names given to bookmarks are not copied. The bookmarks stay as they are.
- **Subfolders in the favorites**: `S` (or `:subfolder name`) in the list of favorites makes a subfolder in a folder, as _Article_ with _Pending_ and _Done_ (one level: no subfolders in subfolders). Subfolders have colors, open and close, and are renamed, moved and removed as folders; favorites move into and out of them with `V` and `M`. In `favorites.txt` a subfolder is a folder line with a blank space in front, and its favorites start with two. The bookmarks of the Jump menu have subfolders too (`S`, `:subfolder`), and `:import favorites` copies the subfolders.
- **Notes on favorites**: `N` (or `:note`) writes a note for a favorite or a folder in the editor (several lines, references, links). The notes are kept in `favorites.txt`, on the line after their favorite, never next to the files (which may be in a Git repository). `/text` also finds the favorites and folders whose note (or folder name) has the text. A note saved before a jump from the editor (`Ctrl+O`, `:book`) is kept, each note is written in a file of its own for the editor (so a recovery copy is only offered for its own note), and `P` or `:fav` asks before taking a favorite with a note out of the favorites.
- **Note and Peek below the favorites**: two panes below the list show the note of the selected item and the top of the file (what is in a directory or a folder). They follow the selection and cannot be focused; the peek reads only the start of the file. `:panes` hides or shows both, `:peek` the peek, kept in the settings `favoritepanes` and `favoritepeek` (on from the start).
- **New file from the favorites**: `W` (or `:new`, `:new name`) in the list of favorites makes a new file with the box of the start page, starting in the folder of the selected favorite (`Tab`: another folder, the favorite's folder among the places). The file becomes a favorite below the selected item (first in a selected folder), and is opened in the editor; the list comes back after. The box of a new file tells on a line of its own that `Tab` chooses another folder (also on the start page and when a blank page is saved). The key hints of the favorites show `W New` and `V Move` (`D Remove` is in the help).
- **The bookmarks of the Jump menu as the favorites**: `W` (or `:new`, `:new name`) makes a new file with the box of the start page, bookmarked below the selected bookmark and opened in the editor; `N` (`:note`) writes a note for a bookmark or folder, kept in `bookmarks.txt`; Note and Peek panes below the list (`:panes`, `:peek`, settings `bookmarkpanes` and `bookmarkpeek`); `/text` finds notes; removing a bookmark with a note asks first. `:import favorites` copies the notes too (to a bookmark without one; a note a bookmark has is kept). `:book 3` works in the Jump menu itself. The key hints of the Bookmarks tab are those of the favorites (`D Remove` and `X Rename` are in the help), and the row of the filter tells at its right end that `:` gives the commands. On every tab the number of the selected place and how many there are (`5/8`) show at the right of the bottom line of the menu, and moving the selection only draws what changed.
- **An 80x24 terminal is enough**: Blyant draws at least 79 columns by 23 rows (it was 80 by 23), so a window of 80 by 24, the size of a classic terminal (LXTerminal on a Raspberry Pi, a Linux console, many SSH sessions), is no longer one column too small; the last column and row of the window stay free, as before. The key hints use their line to its end, so they show as many hints as before. With _Automatic size_ off, a size set by hand that does not fit the window is told about when Blyant starts and before a page is drawn (once for a size of the window), with the choice to let the size follow the window.
- **`Ctrl+O` on every tab of the start page, the color schemes and the logos**: the Jump menu opens from the pages of Configuration and from Help too, not only from the Start tab, and on every tab of the color scheme and logo editors (not while text is typed in a field). A jump that leaves an editor asks about changes that are not saved first, as `Esc` does, and a jump to the editor that is open keeps it as it is. A jump that would leave a page opened on top of another (Color schemes opened from the editor, from the Jump menu) is not made while the page below has changes that are not saved: you are told, and save or discard them there.
- **`:favorites` (`:favs`) on the start page** opens the favorites of the file browser at once, as in the file browser (closing them shows the file browser).
- **Counts in the lists**: in the panes of the file browser (the pane with the focus; also when a folder is picked), the favorites, the file history, the directory hotlist, the search results and the Jump menu, `5j` and `5k` move 5 rows down and up, and `5gg` (or `5G`) goes to row 5, as in the editor. The count is shown while it is typed (at the bottom right, or next to / Filter in the Jump menu), `Esc` drops it, and while a favorite, a directory of the hotlist or a bookmark is moved with `V`, `3j` moves it 3 steps.
- **Removing a favorite asks first**: `D`, `P` and `:remove` in the list of favorites ask before removing a favorite, a folder (also an empty one) or the marked favorites, and tell when notes or subfolders go with it. `u` still puts it back.
- **No limit to the bookmarks**: there could be at most 100 before.
- **`:protect off`** in the file browser lifts the protection of Blyant's own files (the data directory, `settings.ini`, `favorites.txt`, `history.txt`) for the session, so they can be renamed, moved and deleted; `:protect on` restores it, and it is on again at every start. _UNPROTECTED_ shows at the top right while it is off, and the question before deleting tells that Blyant uses the file.
- **Columns in the lists of the file browser**: the favorites, the file history, the directory hotlist and the search results have lines between their columns and labels in the divider line, so a long list is easier to read: _Name_, _Path_ and _Info_ in the favorites (size, `<DIR>`, _(missing)_, number of favorites) and the search results (_Line_ in place of _Path_ when a text was searched), _Name_, _Path_ and _Opened_ in the history, _Name_ and _Path_ in the hotlist.
- **Start on a blank page**: a third choice for startup on the General page of Configuration (`startmode=blank`): Blyant opens on a blank page, and the start page comes when it is closed.
- **The kind of new files**: _New files and blank pages_ on the General page picks the kind of a new file whose name has no extension, and of a blank page: Markdown (the default), plain text, HTML, CSS, JavaScript, JSON, XML, C#, PHP or INI (setting `filetype`). It is used by `N` and `:new` on the start page, in the file browser and in the editor, and a blank page is colored as that kind.
- **Recover unsaved text**: `R` (or `:recover`) on the start page, shown only while there are recovery copies, lists them (blank pages and files, the newest first, with the start of the text) to open one, or `D` to delete one.
- **The Default color scheme** highlights the tab with the focus (cyan on black), with a white corner.
- **_Open file_ on the start page is now _File browser_**, as it does more than open files (the key is still `F`, and `:file` and `:open` still work).
- **New file in another folder**: on the start page, `Tab` in the box of a new file (`N`, `:new`) chooses the folder: the folders of the two panes of the file browser, and the folder picked last (`1` to `3`, or `j`/`k`, `gg`/`G` and `Enter`), or `B` to pick one in the file browser. The name typed is kept. `:new name` shows the box too, with the name filled in.
- **Fixes from a code review**:
  - A recovery copy put off with _Decide later_ was written over by the next change of the file. Now the new changes get a copy beside it, and both are kept
  - `p`, `P`, `:dup` and a block put on the last line of a read-only text (a peek, a comparison) stopped the editor with an error. They are refused, as other changes are
  - When the list of added projects (`projects.txt`) could not be read for a moment (held by a sync program), adding a project wrote a list with only that one. Now it is not changed, and you are told
  - Saving the settings file from the editor did not tell when the write failed, and marked the text as saved
  - The paste bin file could be one of Blyant's own files (as `settings.ini`), which every yank then replaced
  - The data directory is chosen once: a folder `data` made later in the directory Blyant was started in no longer takes its place in the middle of a session
  - A count given to `.` takes the place of the count of the change, as in Vim (`3x` and then `2.` deletes 2 characters, not 6)
  - Shell scripts: a here-string (`<<<`) and a shift in arithmetic (`$((1 << n))`) are no longer read as the start of a here-document
  - Rust: a raw string over several lines (`r#"...`) ends at its own end (`"#`), not at a quote in it
- **More fixes from the code review**:
  - The bottom line of the editor no longer runs past the edge when all that is at its right (spelling, recording, the kind of file ...) is wider than the window: only the line and column are kept
  - C and C++: a comment on a line of the preprocessor (`#include "a.h" /* ...`) is colored as a comment, and goes on to the next lines
  - Markdown: a block of code ends only at a fence of the same kind (```` ``` ```` or `~~~`), at least as long, with nothing after it
  - `gU`, `gu` and `~` change case the same way whatever the language of the computer is (on a Turkish system `i` became `İ`)
  - Smartcase: a letter after a backslash (`\S`) no longer makes a search match case
  - `blyant --help` and `blyant --version` (also `-h`, `-v`) are answered in the terminal; before, `--help` was offered as a file to make
  - `B` in the Jump menu no longer forgets the bookmark that `u` could put back
  - The languages are picked with `1` to `9` and then letters: with 10 or more, typing `1` picked the first at once
  - Texts cut for the screen count terminal cells (wide characters take two), and a text that fits exactly is no longer cut
- **Small fixes for Linux and macOS**: after `Ctrl+Z` and `fg`, every page is drawn again by itself (it was only the editor); the key typed right after the `Esc` that closes a peek is no longer lost; a terminal started from GNOME Terminal or LXTerminal (kitty, WezTerm, Alacritty), and tmux, are no longer told that they may not take the clipboard; and a partial copy taken out of the trash is logged
- **Hints on the start page**: to the right of the menu of the Start tab, a hint tells about one of nine features (the command line, the Jump menu, favorites, Markdown completions and `:surround`, recovery copies, the trash, split and compare, peeking, project notes), the next one each time Blyant starts. `X` hides them, and Configuration (System) shows them again; while they are hidden, nothing is written for them. Settings `hints` and `hintindex`
- **The commands are listed while you type them**: on every command line (the start page, the file browser and its lists, the Jump menu, projects and the editor), a box above it lists the commands of the page in columns, narrowed to those that start with what is typed, as `Tab` completes them. A command typed whole is highlighted, and the box tells what it does, from the help. After a space it lists what can follow (`:play ` the macros, `:surround ` the completions). It can be turned off in Configuration (General), setting `commandlist`
- **The Jump menu has columns** as the lists of the file browser: Name, Command (`:book 3`; When on Recent and History), Path and Type, with lines between them and their names in the line above the list. The command is right after the name, also in a wide window (it was at the right edge, far from the name), and the path shows where each place is
- **`:surround /bold`** puts a completion around the selection: the text goes in place of its `$0`, so `/bold` makes it bold, `/link` a link and `/code` a block of code; your own completions with `$0` work too. Each line selected with `V` is surrounded by itself (or all of them, with a completion of several lines), and each line of a block. `Tab` after `:surround ` goes through the completions for the kind of text. (`:wrap` was taken: it turns the wrapping of lines on.) Tab also completes what follows a command after a range now (`:'<,'>surround /b`)
- **An icon for Blyant.exe**: a pencil in the colors of the Default scheme, writing a cursor, in all the sizes Windows uses (16 to 256 pixels). It is drawn by `tools/icon.py`, which also writes it as SVG (`Blyant/Blyant.svg`), for a web site
- **Linux, macOS and the Raspberry Pi** (from a review for those systems):
  - On a terminal of 8 colors (the text console of Linux and of a Raspberry Pi, `TERM=linux`) the bright colors are shown: dark gray was black there, so dividers, frames, borders and line numbers could not be seen, and white looked as gray
  - `Esc` and a key typed quickly after it (or while the screen was drawn) came from the terminal as one key with Alt, and the key was typed into the text: they are two keys again
  - `Ctrl+\` (and `Ctrl+Break` on Windows) no longer stops Blyant at once, without a recovery copy
  - After `Ctrl+Z` and `fg`, the editor is drawn again by itself
  - A yank in a terminal that drops the clipboard sequence (the text console, LXTerminal and other VTE terminals, the Terminal of macOS) no longer says "Copied to the clipboard": it says to use the paste bin
  - A folder `data` in the directory Blyant is started in is used only when it is Blyant's own (it has `settings.ini`): the `data` folder of a web site or a program is no longer filled with Blyant's settings, copies and trash
  - A `data` folder next to the program that this user cannot write to (made when Blyant was run with `sudo`) is not used: the one in the user's application data is
  - A recovery copy that cannot be written is told once in the editor, instead of failing without a word
  - When the terminal is closed while a box waits for a key (as "Save changes?"), the last changes are copied too
  - Saving checks with the system whether this user may write the file (also a file of another user), and a file system that cannot keep the permissions (FAT on a memory stick) no longer stops the save
  - The names of recovery copies and of files in the trash can be made on every file system (FAT and exFAT too): `: ? * " < > | \ /` become `_`, and long names are shortened (the real name is kept in the copy and in the list of the trash)
  - A folder moved to the trash on another drive that cannot be copied whole (a full disk) is removed from the trash again, and the original stays
- **The installation guide** gave the smallest window as 80 columns and 23 rows: it is 81 by 24
- **An empty line is yanked as a line**: `yy`, `dd`, `cc` and `V` `y` on an empty line put it in the register, as in Vim. Before, the register kept what was in it, so `p` put that back instead of the empty line.
- **Speed and limits** (from the code review):
  - Changes inside lines no longer move the layout of all the lines after them: `:%s` on 100 000 lines takes a tenth of the time, and undoing it is at once
  - `:dup` puts in no more text at once than `p` does (10 million characters)
  - A search or `:s` of many lines stops after 10 seconds in all (each line still has 2), and a `:s` that is stopped puts back the lines it had changed
  - A yank of more than about 75 KB is not sent to the clipboard of the terminal, which would drop it (or be held for seconds): the message tells, and the paste bin gets it when it is on
- **Linux and macOS**: a page drawn past the edge of a window that is too small is now noticed on every page (it was only in the editor), and a file that may not be written (`chmod -w`) is not saved over, as on Windows
- **Releases**: `publish.ps1` runs the tests first (`-SkipTests` leaves them out), stops when the versions in `Blyant.csproj` and `DialogText` differ, replaces the old archives of what it publishes, and says that it needs PowerShell 7.3. `tools/checklang.py` ends with exit code 1 when a language file has errors. Markdown files are kept with LF by git (`.gitattributes`)
- **Tests**: the tests that read the source also see the Async ways of writing, `FileInfo` and `File.Open` with a mode not named, `File.Replace`, interpolated texts on the screen, and commands in switch arms; tests that only run on one system, or need symbolic links, are shown as skipped where they cannot run
- **A picture of h, j, k and l** in the quick guide and the editor guide shows them as the arrow keys they are, below their rows.
- **PowerShell, batch files and shell scripts are colored**: `.ps1` (`.psm1`, `.psd1`), `.bat` and `.cmd`, and `.sh` (`.bash`, `.zsh`, `.bashrc`) files get colors in the editor: comments, strings (here-strings and here-documents over several lines), the words of the language, numbers, and as names the variables (`$name`, `%name%`, `${name}`) and the labels of batch files. A file without an extension is colored by its first line, as `#!/bin/bash`, `#!/usr/bin/env python3` or `#!/usr/bin/env pwsh` tells. `:syntax ps`, `:syntax bat` and `:syntax sh` color a text as one of them.
- **C, C++, Rust and Python are colored**: `.c`, `.h`, `.cpp`, `.hpp` (and the other names of C++ files), `.rs`, and `.py`, `.pyw` and `.pyi` files get colors in the editor, in the colors of C#: comments, strings, the words of the language, numbers, and as names the lines of the preprocessor (C/C++), attributes and lifetimes (Rust) and decorators (Python). Macros in Rust (`println!`) are colored as words. Raw strings of C++ and Rust and strings in three quotes in Python go over several lines. `:syntax cpp` (or `c`), `:syntax rust` and `:syntax py` color a text as one of them.
- **Settings files are colored**: `.ini` files (and `.cfg`, `.conf`, `.editorconfig`) get colors in the editor: comments, `[sections]`, the names, and the values (numbers, `true`/`false` and the like, and text). Blyant's own `settings.ini` is colored too, also when edited from Configuration. `:syntax ini` colors any text as INI.
- **The type of `.blyant` files**: the file browser and the bottom line of the editor show the type of a file whose name starts with a dot and has no other extension, as the information box (`I`) does: `.blyant` is `BLYANT`, `.gitignore` is `GITIGNORE`. Before, it was left empty.
- **Recovery copies**: while a file has changes that are not saved, a copy of the text is kept in `recovery` in the data directory: written when you stop typing for 2 seconds (and at least every 30 seconds), and when the terminal window is closed or the computer shuts down. It is removed when the text is saved or the changes are given up. Opening a file that has a copy asks what to do: open the recovered text, show the differences, keep the file as it is, or decide later. `:recovery` in the file browser goes to the copies; the setting `recovery` (Configuration, Editor) turns them off. The same on Windows, Linux and macOS.
- **Files are never emptied before they are written**: the paste bin is now replaced safely too (written to a temporary file first, as files are saved), and making a new file (`N` in the file browser, or a file given at startup) never empties a file that has come in the meantime. A peek can never be saved.
- **The log is written to `log.txt`** in the data directory, with the date, so it can be read after Blyant is closed; at startup a file larger than 1 MB is renamed `log.old.txt`. Deletions tell whether they went to the trash.
- **Jump menu**: a **Projects** tab after Recent, with the projects in their colors; `Enter` shows the one picked in the file browser.
- **Color scheme Bright Typist**: a new built-in scheme with black text on a white background, as on paper, and dark blue, dark yellow and dark magenta for the colors of Markdown and other files.
- **Automatic size is on from the start**: the screen follows the size of the terminal window, also after _Reset all settings_, and with a settings file that does not have `autosize` in it (`autosize=false` turns it off).
- **Ctrl+C** does not close Blyant any more, which lost text that was not saved: the editor tells how to close it (`:q`). Where the terminal has a selection, `Ctrl+C` still copies it.
- **The editor follows the terminal window** when it is resized (with _Automatic size_ on), also on Linux and macOS, where a resize was not noticed: when the size has stayed the same for a moment, the text is wrapped in the new width (a split keeps half for each pane) and drawn again. Before, the text could stay blank after a resize. With a fixed size, the question about a window that is too small goes away by itself when the window is made large enough.
- **The pages follow the terminal window too**: the start page (all its tabs), the file browser, the favorites, the file history, the directory hotlist, the search results and the Jump menu are drawn again in the new size as soon as the window has kept it for a moment, as the editor is. Before, they followed it only after a key was pressed. A message shown on the page stays, and so does a count being typed. With a fixed size, a window made too small asks the question at once.
- **The list of commands leaves nothing behind in the editor**: when the command line closed, the right edge of the box of commands above it stayed on the screen, in the last column of the text area (which the text never uses). That column is now written over too.
- **`f` `t` `F` `T` find on all the lines**: in the editor they go on to the lines below (`F` `T`: above) when the line has no more of the character, also with `;` `,`, a count and an operator (`dfx` deletes to the next `x`, wherever it is). `t` before a character that starts a line goes to the end of the line above. The character found is highlighted everywhere in the text (in the color of the selection arrow of the color scheme) until a key other than `;`, `,`, a count or another `f` `t` `F` `T`; `Esc` takes the highlight away before it closes the editor. Not with an operator, which changes the text.
- **Jump to a word with `Enter`** in the editor (as mini.jump2d for Neovim): every word that starts on the screen gets a label of one or two letters, shown over its first characters (the second dimmer), and typing the letters at a word moves the cursor there. A letter shared by several words leaves only those. `Enter` again goes to the first word left, and `Esc` cancels. In Visual mode it extends the selection. With a count or after an operator, `Enter` still goes down to the first character of a line. Not made while a macro is recorded.
- **A block selected to the ends of the lines** (`$` in VISUAL block mode) stops at the cursor again after `f` `t` `F` `T` and the jump to a word, as after the other motions; before, `d` still took each line to its end.
- **Blyant starts on Linux and macOS again in GNOME Terminal and other VTE terminals**: it stopped at startup with an exception ("The type initializer for Blyant.SystemClipboard threw an exception"). Whether the terminal drops the clipboard sequence was found while the class was set up, before the lists it looks in were there; it is now found when it is first needed. Windows was not affected. A test reads the source for this mistake, as it cannot happen on Windows.
- **Peek** (`V`, `:peek`) keeps the focus in the list: the peek follows the selection, so files are gone through with `j` and `k`. `Tab` goes into the peek (to scroll and search; `Tab` or `Esc` goes back). The pane of the peek is labeled PEEK, with the name of the file at its top, and `V` or `Esc` ends it, as do the keys that use the other pane. The peek shows the file without word wrap, also when the setting `wrap` is on; `:wrap` in a peek is for that peek only, and is not saved.
- **Editor**: `:projects` (`:proj`) shows the projects in a list; the one picked is shown in the file browser, as a jump (changes that are not saved are asked about first).
- **New files are Markdown**: a new file whose name has no extension gets `.md` (`chapter 1` is `chapter 1.md`): `N` and `:new` in the file browser, New file on the start page, and `:new` in the editor. A name that starts with a dot (`.gitignore`) is kept as it is.
- **The list of colors** (the colors of a scheme, of a favorite, a bookmark or a folder): each color has a letter that picks it at once, as the choices of the start page: `A` Black ... `U` White (leaving out `g` `j` `k` `l` `q`, which the list uses), and `X` for _[Default]_. `1` to `9` select the first nine colors.
- **Completing words**: the words of the Markdown list and of the list for all text in a new `completions.txt` start with `/`, so they are not offered while you write prose (`co` no longer offers a code block): `/h1` to `/h6` (headings), `/bold` (`**$0**`), `/italic` (`*$0*`), `/bolditalic`, `/strike`, `/inline` (code in a line), `/quote`, `/list`, `/numbered`, `/task`, `/done`, `/code`, `/table`, `/hr`, `/link`, `/image`, `/url`, `/footnote`, `/footdef`, `/frontmatter`, `/comment`, `/note`, `/warning`, `/todo` and `/lorem`. The word `JavaScript` is in the JavaScript list. A file made before keeps its lists. When the whole word of a completion is typed (`/bold`, with `/bolditalic` shown too), `Tab` completes with it at once. A completion is shown with `...` where the cursor goes (`**...**`, `<div>...</div>`), so one of marks only can be read. Completing is on from the start, and the file is made at startup when there is none, so it is ready the first time (a file that is there is never written over; a settings file with `autocomplete=false` keeps it off).
- **Startup**: `startmode` is `select` (the start page) or `editor` (the file browser); `notes`, of Marbles, shows the start page.
- **Help, guides**: the help, the quick guide and the short guides tell of files and projects; the Note Management guide is now the **Projects guide**. The guides are `Guide-to-start-page.md` (the start page, projects and the file browser) and `Guide-to-jump-menu.md` (the Jump menu, color schemes and logos).
- **Its own data**: when the program directory cannot be written to, Blyant keeps its data in `Blyant/data` in the user's application data (Marbles uses `Marbles/data`), so the two programs can be used side by side.
